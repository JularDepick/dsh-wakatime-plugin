# Tag&Release 规范

## 版本号

遵守 `v<主版本号>.<次版本号>.<修订版本号>` 格式,例如 `v0.1.0`.

> README的版本徽章显示文字中,版本号不带v字母前缀

## Tag

遵守 `<版本号>` 格式.

## Release

遵守 `<版本号>-dsh-<最高支持的dsh版本号>` 格式,例如 `0.3.0-dsh-0.2.1-rc.3`.

> Release 名中的 dsh 版本取该产物支持范围的**上界**.

> 同一份产物支持的是包清单声明的**实测区间**(`engines.dsh` 与七个宿主包的 peer 范围使用同一区间): 区间内的小版本 dsh 升级无需为每个 dsh 版本单独发布插件, 当前区间为 `>=0.2.1-rc.1 <=0.2.1-rc.5`.

> 区间之外(含区间上界之后的正式版与后续预发布)一律拒绝安装与启动, 因此每当实测通过更高版本时必须成对推进 `engines.dsh` 与 peer 的上界并发布新的 Release; 未实测的版本不进声明.
> 区间下界只在实测覆盖时下探, 不要为"看起来兼容"而放宽.
> 示例: 0.3.0 版本对应 Release 名 `0.3.0-dsh-0.2.1-rc.3`(上界即区间上界).
