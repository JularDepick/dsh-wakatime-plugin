# Tag&Release 规范

## 版本号

遵守 `v<主版本号>.<次版本号>.<修订版本号>` 格式,例如 `v0.1.0`.

> README的版本徽章显示文字中,版本号不带v字母前缀

## Tag

遵守 `<版本号>` 格式.

## Release

遵守 `<版本号>-dsh-<最高支持的dsh版本号>` 格式,例如 `v0.2.1-dsh-0.2.1-rc.1`.

> Release 名中的 dsh 版本取该产物支持范围的**上界**.

> 自 v0.2.1 起同一份产物支持 dsh 0.2.x 范围内的多个版本: 包清单以 `engines.dsh` 声明范围(0.2.1-rc.1 起的启动器按它判定),并对宿主包声明覆盖两端的 peer 范围(0.2.0-rc.2 的启动器与包管理器按它判定).因此 0.2.x 范围内的小版本 dsh 升级不再需要为每个 dsh 版本单独发布插件.

> 当跨出受支持的次版本(例如进入 dsh 0.3.x)时,才必须迭代插件版本号并发布新的 Release,同时更新 `engines.dsh` 上界与 peer 范围.
